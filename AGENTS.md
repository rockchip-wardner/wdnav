# AGENTS.md

Python bindings for Rockchip MPP / RGA / V4L2 / DmaHeap / GPU (import name `wdnav`).
Project background and dependencies live in [README.md](./README.md); this document only
covers the constraints an AI collaborator must follow.

## Important

- SPS / PPS generated by Python's MPP calls differ from C's MPP calls. Codec-related
  features go through the high-level C shim layer (`cshim_video_*.c`) and must not be
  bypassed.

## Contribution & Submission Workflow (important)

> **This repository does not accept PRs that contain AI-generated source code.**

- Found a bug / abnormal behavior / doc error → **open an ISSUE directly**, attaching:
  - Repro command (`python samples/xxx.py ...` or a minimal code snippet)
  - Input file / device path / hardware model (Rockchip SoC, kernel, driver version)
  - Full traceback / `dmesg` / `journalctl` snippets
  - Expected behavior vs actual behavior
- PRs that modify source code **must** be authored by a human and include regression
  test records from real hardware.
- The default action of an AI assistant in this repo is: **read → explain → suggest a fix**;
  **do not** produce a patch for the human to submit.

## API Design Principles

- Compatible with `cv2` usage conventions, but has **no runtime dependency on `cv2`**
- `pyav` is used **only** for audio/video demux / mux; **no** software encode or decode
- All encode / decode goes through MPP; colour conversion / scaling goes through RGA;
  display goes through Mali EGL
- **No software fallback, no safety net**: if MPP / RGA / Mali cannot do it, raise an
  error. Do not use `pyav` to do jpeg / h264 / h265 software codec
- When wrapping / debugging MPP / RGA, **only reference their `sample` / `test` source
  code and public headers**. Do not read the MPP / RGA library implementation itself
  (MPP is only allowed to be read under `test/`, `utils/`, `inc/`)
- Prefer the zero-copy interfaces (`read0` / `write(frame0)`) by default. Do not fall back
  to numpy / BGR unless necessary — the next hardware consumer would then have to fetch
  contents from the virtual address, which is inefficient. Hardware codec prefers NV12
- Rate control: **jpeg uses FIXQP; all other codecs use CBR**

## Modification Rules

When changing one feature, do not break others. If a shared module must be changed,
real-device regression must be run across all affected features.

- Changes touch only the target feature and its direct dependencies; **no drive-by refactor**
- Changes to shared modules (`mpp.py` / `rga.py` / `encoder.py` etc. used by multiple
  callers, native `.so` ctypes bindings) **must** run all relevant real-device tests:
  - All `samples/` examples that use the module
  - `tests/test_smoke.py`
  - End-to-end integration paths of the callers
- No "skip the test" or "the code looks right" allowed
- Failure → fix until everything passes, then hand off
